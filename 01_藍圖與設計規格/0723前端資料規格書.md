# AI SERVO PLATFORM — 前端資料規格書 (Frontend)

> 給 Frontend 團隊：本文件定義你需要建置的畫面、呼叫的 API、訂閱的 WebSocket、以及資料視覺化方式。

## 一、前端整體職責

```
你負責:
1.
  主控制按鈕如下:  ON/OFF/CYCLE START/STOP/EMERGENCY STOP
  訓練狀態顯示:   a.-  HEAVY TRAIN/MIN TRAIN / MS TRAIN
                 b.--  FULL RETRAIN / FINE-TUNE  / INFERENCE ONLY
   狀況顯示: ALARM / ERROR/ NORMAL
   模式顯示:  顯示工況情境模型
  2. 主畫面 — 即時監控 (DV/ylabel/延遲/Fallback)


  3. L2 畫面 — 微調狀態 + 歷史趨勢
  4. L3 畫面 — AutoML 模型排名 + 特徵重要性
  5. Shadow 畫面 — A/B 比較 + 決策展示
  6. SHAP 畫面 — 根因分析 + 設備建議 + 圖表
  7. Scenario 摘要 — 三 scenario 狀態卡 + 時間軸
```

### 3.2 DV 儀表規格

| DV_norm 範圍 | 顏色         | 控制模式      | 前端行為                    |
| ------------ | ------------ | ------------- | --------------------------- |
| 0.0 ~ 0.2    | `#00FF00` 綠 | Normal        | 正常顯示，無動作            |
| 0.2 ~ 0.4    | `#FFD700` 黃 | Normal (記錄) | 顯示注意標記                |
| 0.4 ~ 0.6    | `#FF8C00` 橙 | Diagnosis     | 背景閃爍警示，觸發診斷通知  |
| 0.6 ~ 0.8    | `#FF0000` 紅 | FineTune      | 紅色警報，顯示微調進度條    |
| 0.8 ~ 1.0    | `#000000` 黑 | Safe          | 黑色警告，顯示降速/停機訊息 |

**實作注意：**

- 後端回傳的 `control_mode.hmi_color` 為 color name (green/yellow/orange/red/black)
- 前端可用此欄位直接設定顏色，無需自行計算 DV_norm
- DV 顯示原始值 (非 0~1)，`control_mode.dv_norm_predicted` 為正規化後的值 (0~1)

### 3.3 即時趨勢圖規格

- X 軸：時間 (自動縮放 1min / 5min / 1hr)
- Y 軸：DV 原始值
- 折線顏色依 DV_norm 動態變色
- 圖表下方有時間範圍切換按鈕
- 超過 1ms 延遲紅線需醒目提示

### 7.3 SHAP 圖表規格

**Force Plot (瀑布圖)：**

- 從 base_value 開始，每項 feature 的 SHAP value 依序堆疊
- 正向貢獻 (紅色) / 負向貢獻 (藍色)
- 最終到達 current_prediction
- X 軸顯示累積值，右邊顯示最終預測值 vs 實際值

**Global Importance 條形圖：**

- 橫條圖，依 mean_abs_shap 降序
- LightGBM 模型額外顯示雙條圖 (gain 藍 + split 橙並排)

**Beeswarm 散佈圖 (從 `/api/v1/shap/summary`)：**

- X 軸：SHAP value (影響方向)
- Y 軸：feature (依重要性排序)
- 點顏色：feature value (紅高藍低)
- 滑鼠懸停顯示 feature name + SHAP value + feature value

**設備參數建議表格：**

- 欄位：Feature | SHAP 貢獻 % | 設備參數 | 建議動作 | 當前值
- 背景色依貢獻 % 深淺

```typescript
  private connections: Map<string, WebSocket> = new Map();
  private reconnectAttempts: Map<string, number> = new Map();
  private messageBuffers: Map<string, any[]> = new Map();

  connect(topic: string, scenarioId?: string) {
    const url = scenarioId
      ? `ws://host/ws/${topic}?scenario_id=${scenarioId}`
      : `ws://host/ws/${topic}`;

    const ws = new WebSocket(url);

    ws.onopen = () => {
      this.reconnectAttempts.set(topic, 0);
      // 補發斷線期間遺失的訊息
      this.flushBuffer(topic);
    };

    ws.onmessage = (event) => {
      const data = JSON.parse(event.data);
      this.routeMessage(topic, data);
    };

    ws.onclose = () => {
      const attempts = this.reconnectAttempts.get(topic) || 0;
      if (attempts < 10) {
        const delay = Math.min(1000 * Math.pow(2, attempts), 30000);
        setTimeout(() => this.connect(topic, scenarioId), delay);
        this.reconnectAttempts.set(topic, attempts + 1);
      }
    };

    this.connections.set(topic, ws);
  }

  private routeMessage(topic: string, data: any) {
    // 根據 topic 將資料派發到對應的 React component
    switch (topic) {
      case "ws/l1/summary":
        store.dispatch(l1Slice.actions.updateSummary(data));
        break;
      case "ws/l2/finetune":
        store.dispatch(l2Slice.actions.addFinetuneResult(data));
        break;
      case "ws/shap/diagnosis":
        store.dispatch(shapSlice.actions.setDiagnosis(data));
        break;
      case "ws/fallback/escalation":
        store.dispatch(fallbackSlice.actions.addEscalation(data));
        showAlert(data.alert);
        break;
      case "ws/control/status":
        store.dispatch(controlSlice.actions.updateStatus(data));
        break;
      case "ws/expert/notification":
        store.dispatch(expertSlice.actions.addNotification(data));
        break;
    }
  }

  disconnectAll() {
    this.connections.forEach((ws) => ws.close());
  }
}
```

## 十八、注意事項（補充）

| 事項                 | 說明                                                                                                                |
| -------------------- | ------------------------------------------------------------------------------------------------------------------- |
| **DV 非 0~1**        | DV 是 per-run 常數 (各 scenario 尺度不同)，請用 `control_mode.dv_norm_predicted` (0~1) 做顏色判斷，不要用原始 DV 值 |
| **延遲紅線**         | L1 延遲若 p99 > 1ms 代表模型服務異常，需在延遲圖上畫紅線 + 顯示警報                                                 |
| **WebSocket 降採樣** | 50kHz 全量推播對前端渲染壓力大，後端已降採樣至 1kHz。前端每秒更新圖表即可，無需即時渲染                             |
| **SHAP 圖表載入**    | beeswarm 資料量較大 (200 samples × 10 features)，建議 lazy load，預設只顯示 force plot                              |
| **LightGBM 雙指標**  | `lightgbm_importance` 含 gain + split 雙指標，前端用雙條圖並排顯示                                                  |
| **IEC 合規匯出**     | 匯出按鈕需將 `shap_logs.jsonl` + `fallback_logs` + `models.jsonl` 合併為 IEC 標準格式                               |
